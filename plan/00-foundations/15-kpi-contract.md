# 15 — KPI definitions and evidence contract

This is the canonical definition for foundation 01, M4-07 and M10-08. M4-07 implements the read models and queries; M10-08 archives their query text, parameters, schema version and results. These are planned query contracts, not evidence that the queries or telemetry exist today.

All ranges use UTC `[start, end)`. Exclude sandbox/demo/dry-run data. Count each task once using its first admitted assignment; retry decisions do not inflate routing share. Report numerator, denominator, excluded/unknown count, coverage and confidence. Zero denominator produces null, never zero or success. Fewer than five eligible units gives insufficient data; five units is not a statistical-confidence claim.

| ID | Definition and query contract | Missing data and target |
|---|---|---|
| K1 off-top-tier share | Select one first-admission decision per real task assigned in range. At that decision's catalog version, count selected costTier below that provider's known maximum / eligible assigned tasks. Query: `100 * count(eligible where chosenTier < providerMaxTierAtDecision) / count(eligible)`. | Missing catalog/decision/tier excludes that task and increments unknownTasks; retries do not add rows. ≥60% is an observed product target, not quality proof. |
| K2 productive window utilization | For each closed account + bucket + unit + window instance with official allowance and complete comparable attribution, sum official usage attributed without overlap to tasks finalized successfully / official available allowance for that same window. Query per bucket/window: `100 * sum(successfulAttributedUsage) / officialAllowance`. Final success means completed declared deliverable or merged code with required acceptance checks; merely approved/in-progress tasks are not final successes. | Exclude unknown allowance, ambiguous attribution, estimates and external-client usage that cannot be attributed. Report covered/total windows. Never add tokens to credits/percentages, or sum units across buckets. ≥80% is evaluated per covered window; no full-coverage claim from a covered subset. |
| K2 diagnostic total usage | Official closing used / allowance for each covered window, regardless of task outcome. | Label total usage; never substitute it for productive utilization. High usage is not inherently success. |
| K3 reroute success | Distinct tasks rerouted in range that finalize successfully / distinct tasks rerouted in range, observed through report time. | Pending tasks stay in denominator with pending count; count repeated reroutes once. |
| K4 quota-blocked time | Sum task seconds blocked specifically for quota / sum task nonterminal seconds, clipped to range. | Unknown reason intervals reported separately; overlapping observations deduplicated. |
| G3 independent review coverage | Required-review tasks finalized in range with valid independent-publisher review on the final source revision / all required-review tasks finalized in range. | Unknown publisher, degraded same-publisher review and stale revision count as uncovered; do not count review rounds instead of tasks. |
| G4 avoidable-interruption rate | Pauses with eligible alternative capacity at pause time / all pauses. | Missing capacity snapshots count as avoidable conservatively and are reported separately. This is distinct from K4 duration. |
| G5 recovery outcome mix | Persisted-unaccounted, answerable-recovered, expired, cancelled, delivery-uncertain and capture-gap counts per injected failure boundary/provider mode. | Expired/cancelled records are accounted for but not recovered answerable prompts. Unobserved downtime capture is unknown. |
| G6 recovery timing | p95 detection time for observed classified drift; p95 recovery time only for known, eligible, successfully recovered cases; report timeouts, ineligible and escalated cases separately. | Excluding failed cases must remain visible; timing alone cannot establish recovery reliability. |

M4-07 read models must expose immutable decision catalog versions, task finalization time/outcome, source-correlated usage attribution, official window closure observations and clipped state intervals. Implement each query against hand-calculated fixtures including duplicates, changed catalog tiers, failed/pending tasks, missing identities, external usage and mixed units. Return the definition version alongside the values; API, UI tooltips and release reports share it.

M10-08 requires at least 30 calendar days of real usage with working instrumentation. Record actual observation start/end, build/config versions and excluded periods. Target dates are not evidence. Instrumentation can begin at M8 exit and overlap M9/M10; a materially changed metric starts a new valid observation interval for that metric. Unmeasurable K2 is explicitly N/A with coverage limitations, never claimed as achieved; any required release target lacking evidence remains open unless scope is explicitly revised and recorded.
